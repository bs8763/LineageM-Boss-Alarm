# 운영 전환 안내

이 변경은 검증용 브랜치에서 준비한 구현입니다. 실제 Render 환경·Discord 토큰·외부 DB 설정을 확인하고 단계적으로 반영해야 합니다. 코드 백업과 운영 데이터 백업은 서로 다릅니다.

## 원본과 운영 데이터 보존

- 기준 커밋: `85aee640deb3102ff980addba8e3f77a1c1da3b0`
- 로컬 백업 브랜치: `backup/pre-completion-20261028`
- 원본 Git bundle에는 원본 main과 전체 Git 이력이 포함됩니다.
- 서비스의 기존 `/api/bosses` 응답도 별도 보존했습니다. 확인 당시 등록 수는 0개입니다. 전환 직전 다시 내보내야 그 이후 변경이 누락되지 않습니다.
- 기존 `bosses.json`이 있다면 반드시 별도 내보내 보존하세요. Render의 예전 컨테이너 파일은 새 배포에서 자동 접근할 수 없습니다.

## 중단 위험을 줄이는 전환 순서

1. 기존 서비스는 그대로 두고 새 검증용 브랜치를 GitHub에 올립니다. `main` 자동 배포는 잠시 수동으로 전환하세요. 저장소의 render.yaml은 기존 서비스 설정을 자동으로 바꾸지 않습니다.
2. 외부 PostgreSQL을 준비해 `DATABASE_URL`에 설정합니다. TLS 인증을 유지하세요. 무료 제공량·휴면·만료 조건은 제공자에서 확인하고 자동 유료 전환은 사용하지 마세요. Render 무료 DB는 30일 만료이므로 영구 운영 저장소로 쓰지 마세요.
3. `CLAN_TOKEN`과 `ADMIN_TOKEN`은 서로 다른 24자 이상의 난수로 만듭니다. 토큰·비밀번호를 코드·APK·GitHub 변수에 넣지 마세요. Render 환경변수에만 넣습니다.
4. GitHub Actions의 테스트(PostgreSQL 포함) 및 APK 빌드·lint가 성공했는지 확인합니다. 검증 전 main에 합치지 마세요.
5. 새 환경을 별도로 검사할 때는 **Discord 토큰 없이**, 같은 운영 DB도 연결하지 말고 검증 DB를 씁니다. 두 봇 동시 구동이나 검증 중 운영 데이터 변경을 방지합니다. 무료 Render 서비스를 하나 더 켜면 같은 월간 시간 한도를 함께 소모하므로 검증 후 종료합니다.
6. 기존 데이터 쓰기를 잠시 멈추고 최종 `/api/bosses` 배열을 파일로 내보냅니다. 새 DB에 `DATABASE_URL=... node scripts/import-legacy.js path/to/legacy.json`으로 넣습니다. 빈 DB에서만 가져오며 알 수 없는 이름이 있으면 전체 작업이 취소됩니다. 이름을 기본표와 대조해 명시적으로 매핑하세요. 원본 파일은 보관합니다.
7. 검증에서 `/readyz`, 혈맹 로그인, 31종 목록, 한국시간 예약, 컷·멍의 연동, 관리자 초기화→자동 백업 복구, 파일 복원, 앱 업로드·다운로드를 확인합니다.
8. 기존 Render 서비스에 검증된 커밋과 DB·인증 환경변수를 반영합니다. 기존 서비스 주소를 유지합니다. `healthCheckPath`는 `/readyz`로 지정합니다. 기존 서비스의 수동 설정도 확인해야 합니다.
9. Discord의 `DISCORD_GUILD_ID`, `DISCORD_CHANNEL_ID`, `DISCORD_BOT_TOKEN`을 설정합니다. 봇에 해당 혈맹 채널 보기·메시지 전송 권한이 필요합니다. `REGISTER_DISCORD_COMMANDS=true`로 한 번 기동 후 false로 되돌립니다. 기존 글로벌 명령어는 삭제하지 않습니다. 다른 서버의 명령과 데이터는 이 앱으로 처리하지 않습니다.
10. 새 버전으로 앱과 Discord 양쪽에서 컷·멍을 확인한 후 운영 전환을 완료합니다. 웹 키는 공개 링크와 별개이며 혈맹 구성원에게만 전달하세요.

Render 배포·콜드 스타트 동안 짧은 연결 공백이 생길 수 있습니다. 현재 연결 환경만으로 무중단 배포를 보장할 수 없습니다. 검증 DB·봇 권한·실제 서비스 상태 확인 없이 운영 완료로 판정하지 마세요.

## 시간 규칙

- 컷: 실제 처치 시각 + 리젠 주기. 멍은 0으로 초기화합니다.
- 수동 멍: 현재 예정 시각 + 리젠 주기. 멍 1회 증가. 고정 보스는 다음 고정 시각으로 이동합니다.
- 자동 멍: 예정 시각부터 30분이 지나는 즉시 미확인 처리합니다. 절전 중 여러 주기가 지났다면 한 번에 계산합니다. 기준 시각에서 계산하므로 접속 시각에 따라 리젠이 밀리지 않습니다.
- 고정 보스: 한국시간 고정 시각을 기준으로 다음 일정을 구합니다. 바포메트는 참고표의 출현 창 시작(14:00/20:00) 기준입니다.
- 모든 서버 시간은 UTC ISO로 저장하고 표시·입력은 한국시간입니다.
- 출현 10분/5분 전·출현 예정 알림은 서버가 실행 중일 때 동작합니다. 90초보다 오래 지난 시점의 알림은 재전송하지 않습니다. 절전 중 푸시/명령 즉시 응답은 보장되지 않습니다. 먼저 앱에서 접속해 서버가 깨어난 다음 Discord 명령을 다시 실행할 수 있습니다.

## 보스 기본표

31종은 참고표의 필드 보스 항목을 기반으로 만든 **관리자 확인 전 기본값**입니다. 혈맹의 확정 31종 명단을 확보하지 못했으므로 공식·최신·혈맹 확정 목록으로 취급하지 마세요.

참고: https://upload3.inven.co.kr/upload/2025/09/11/bbs/w2218160429.pdf (작성자 싱검TV)

전체 설정은 `src/catalog.js`에 있습니다. 첨부된 혈맹 정정표에 따라 가스트는 카스트로, 베리스 자리는 네크로맨서(맵 18)로 교체했습니다. 네크로맨서는 정확한 출현 분이 미확정입니다. 자동 넘김과 컷 계산은 관리자 설정 전 비활성입니다. 맵 번호와 주기·고정시간은 관리자 화면에서 수정할 수 있으며, 설정 변경 이력과 변경 전 백업이 남습니다. 가스트→카스트는 기존 예정 시간을 유지합니다. 베리스→네크로맨서는 다른 보스의 일정을 넘겨받지 않도록 이전 항목을 백업·이력에 보존하고 예정 시간·멍·설정을 비웁니다. 같은 변환을 재실행해도 반복 초기화하지 않습니다. 옛 백업을 복원해도 이 규칙을 적용합니다.

## 저장·백업·복구

- Render는 DATABASE_URL이 없으면 시작하지 않습니다. 로컬 파일을 영구 저장으로 가장하지 않습니다.
- PostgreSQL 행 잠금과 트랜잭션으로 동시 수정/전환 시 데이터 손실을 막습니다. 화면에서 오래된 버전으로 수정하면 409 충돌 응답 후 새로고침합니다.
- 모든 상태 변경 전 자동 백업 200개, 최근 이력 1000개를 유지합니다. 조회만으로 백업을 계속 쌓지 않습니다. 자동 넘김과 알림 큐는 같은 DB에 저장됩니다.
- 관리자 화면에서 백업 JSON 다운로드, 파일 복원, 자동 백업 복원, 직전 변경 기록 복구를 제공합니다. 후속 변경이 있으면 단일 기록 복구는 거절합니다.
- 자동 백업도 같은 DB 안에 있어 DB 자체 삭제·만료에는 대비하지 못합니다. 중요한 운영일마다 별도 파일 백업을 받으세요.
- 선택 사항: GitHub Secrets에 `BOSS_ADMIN_TOKEN`, `BACKUP_PASSPHRASE`를 넣고 `Encrypted manual backup` Actions를 수동 실행하면 AES256 암호화 백업을 30일 보관합니다. public 저장소에 평문 혈맹 데이터를 올리지 않습니다. 패스프레이즈는 별도 보관합니다. 복호화는 `gpg --output boss-backup.json --decrypt boss-backup.json.gpg`이며 대화형으로 입력합니다.
- Discord 전송 실패는 DB 큐에서 재시도합니다. 전송 성공 직후 프로세스가 죽으면 중복 알림이 생길 수 있습니다. 표시된 이벤트 ID로 중복을 식별할 수 있으며 정확히 한 번 전송은 보장하지 않습니다.

## 무료 운영 한계

Render는 15분 유휴 시 절전하고, 다음 요청으로 깨어나는 데 약 1분이 걸릴 수 있습니다. 무료 인스턴스 월간 750시간은 워크스페이스 전체 공유이며 트래픽·빌드 한도도 있습니다. 무리한 외부 keep-alive나 5분마다 GitHub Actions를 돌리지 않습니다. GitHub Actions 예약은 지연될 수 있고 알림 서버 대체 용도로 신뢰할 수 없습니다.

장기 무료 운영에는 별도의 지속형 PostgreSQL 계정과 정기 외부 백업이 필요하며, 어떤 무료 제공자의 무기한 무료·가용성도 이 코드가 보장하지 않습니다. 앱에서 사용하지 않는 동안 실시간 보스 알림이 필수라면 현재 무료 서버만으로 그 조건을 충족했다고 할 수 없습니다.

근거: https://render.com/docs/free

## APK

- `Verify and Build Android APK` 실행: Node 테스트 → PostgreSQL 통합 검사 → Gradle 8.9 / Java 17 → Android lint·Debug APK.
- 기본 접속 주소: https://lineagem-boss-alarm.onrender.com
- GitHub Repository Variable `BOSS_APP_URL`로 HTTPS origin을 바꿀 수 있습니다(경로·토큰 불가).
- 성공한 실행의 Artifacts에서 APK와 SHA256SUMS를 받습니다. 14일 보관합니다. 에뮬레이터/실기기 검증은 별도입니다.
- Debug APK는 테스트용 서명을 사용합니다. CI 환경에 따라 서명이 달라 기존 앱을 업데이트하지 못할 수 있습니다. 배포용 고정 서명 키는 추후 비공개 Secret으로 구성해야 하며 이 작업에서 임의 생성·공유하지 않습니다.
- APK는 웹 현황판을 여는 앱입니다. Android 백그라운드 알람·로컬 푸시·오프라인 수정은 지원하지 않습니다. 권한 오류나 저장 실패를 성공으로 표시하지 않습니다.

## 롤백

기존 소스는 백업 브랜치/원본 bundle에서 복원할 수 있습니다. 코드 롤백만으로 구형 서비스에 새 DB 데이터가 자동 이식되지는 않습니다. v2에서 작업한 데이터가 있다면 먼저 관리자 백업을 내보내고, 운영 중 쓰기를 멈춘 다음 구형 `{name,time}` 배열로 명시 변환해야 합니다. 구형 서비스에는 인증이 없으므로 공개 운영 상태로 장기 회귀하지 마세요.
