# 기존 봇을 유지하는 검증 절차

운영 main/Render의 코드·환경변수·토큰은 수정하지 않습니다. 기존 Render에 저장된 토큰을 새로 발급하지 않고 검증 서비스 환경변수에만 재사용할 수 있습니다. Discord 계정 웹 로그인은 필요하지 않습니다.

검증 서비스에 DISCORD_TEST_MODE=true, DISCORD_GUILD_ID, DISCORD_CHANNEL_ID, 기존 DISCORD_BOT_TOKEN을 설정합니다. Neon의 lineagem-boss-test에만 연결해야 합니다. 서버·채널 ID가 없으면 검증 봇은 접속하지 않습니다. REGISTER_DISCORD_COMMANDS=true는 검증 이름 4개만 해당 서버에 개별 등록합니다. 성공 후 false로 되돌립니다. 기존 글로벌 명령어는 수정하거나 삭제하지 않습니다.

기존 main의 봇은 보스등록·보스목록만 처리합니다. 검증 모드는 검증보스·검증보스등록·검증보스목록·검증보스초기화만 처리하며 지정한 서버/채널 외에는 응답하지 않습니다. 검증 응답은 실행자에게만 보이며 자동 알림 큐는 채널로 발송하지 않습니다. 기존 봇의 다른 명령에는 먼저 응답하거나 defer하지 않습니다. 동시 Gateway 연결의 실제 전달 동작은 현장에서 확인하며, 중복 응답이나 운영 명령 장애가 보이면 검증 서비스만 즉시 중지합니다.

## 휴대폰에서 필요한 작업

1. 기존 혈맹 채널의 메시지를 길게 눌러 메시지 링크를 복사합니다. 링크에 서버 ID와 채널 ID가 포함됩니다. 토큰이나 비밀번호는 보내지 않습니다.
2. 준비 완료 안내 후 검증 웹앱을 먼저 열어 무료 서버를 깨웁니다.
3. 같은 채널에서 /검증보스 동작:컷 이름:서드 를 실행합니다. 다음 출현 시간이 현재 시간 + 해당 보스 주기로 설정되고 멍은 0이어야 합니다.
4. /검증보스 동작:멍 이름:서드 를 실행합니다. 이전 예정 시간 + 한 주기, 멍 1이어야 합니다.
5. /검증보스목록 으로 동일한 값인지 확인합니다. 답변의 실행 시간/출현 시간/멍 횟수 화면을 공유합니다.
6. 검증 Render만 재시작한 뒤 /검증보스목록 을 다시 실행하여 동일한 기록이 유지되는지 확인합니다. 관리자 초기화·복구는 테스트 DB에서만 진행합니다.

이 문서는 절차 준비 상태이며 실제 Discord 명령 성공을 증명하지 않습니다. 마지막 세 단계는 사용자의 실제 명령과 검증 DB 이력 대조가 필요합니다. 검증이 끝나면 검증 서비스에서 봇 토큰을 제거하고 검증 명령만 개별 정리합니다. 운영 봇/채널은 유지합니다.

## 일반 채팅 명령 (추가)

`서드 컷`, `서드 멍`, `데스 컷`, `데스 멍`을 일반 메시지로 입력합니다. 기존 슬래시 명령도 유지됩니다. `DISCORD_TEXT_COMMANDS=true`와 `DISCORD_TEXT_CHANNEL_ID`를 명시해야 동작하며, 기본은 꺼짐입니다. 검증 시에는 기존 운영 보탐봇이 볼 수 없는 별도 채널을 지정하세요. `DISCORD_CHANNEL_ID`는 기존 슬래시 검증 채널로 유지할 수 있습니다.

Discord 개발자 포털에서 실제 토큰의 봇 `리니지m 보스알리미` → Bot → Privileged Gateway Intents → Message Content Intent를 켜야 합니다. 이 권한은 봇이 접근 가능한 채널 메시지의 내용을 수신할 수 있게 합니다. 코드는 지정 서버·전용 채널에서만 처리하며 일반 대화/원문은 저장·로그 출력하지 않습니다. 설정은 소유자가 직접 승인하며, 토큰 재발급은 필요 없습니다.

채널 보기·메시지 전송 권한이 있는 서버 구성원만 사용합니다. `DISCORD_COMMAND_ROLE_ID`가 있으면 관리자 또는 해당 역할로 추가 제한합니다. DM·웹훅·봇·다른 채널·90초보다 오래된 메시지는 처리하지 않습니다. 알려진 이름과 정확한 순서를 요구하며 잘못된 이름·미등록 멍·권한 부족은 DB를 바꾸지 않습니다. 같은 메시지 ID의 중복 수신은 DB 트랜잭션과 최근 1000개 처리 영수증으로 차단하며 재기동 후에도 유지됩니다. 수정된 메시지는 처리하지 않습니다. 답변 실패도 이미 저장된 컷·멍을 반복 적용하지 않습니다.

실제 검증: 전용 채널에서 `서드 컷` → `서드 멍` → 오타 이름 컷을 전송하고, 출력 시간과 멍 횟수 및 DB 이력을 대조합니다. 데스도 같은 형식으로 확인합니다. 권한 없는 사용자/역할도 검사합니다. 검증 서버만 재기동한 뒤 같은 값이 유지되는지 확인합니다. 자동 테스트 통과와 실제 메시지 수신 통과는 구분하여 보고합니다.
